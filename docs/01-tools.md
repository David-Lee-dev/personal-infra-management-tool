# 슬라이스 1 — `secrets tools`

## 범위

CLI 를 **돌릴 수 있는가**만 답한다. **누구로 돌아가는가**는 답하지 않는다(→ `account`).
전부 로컬 검사이며 네트워크를 타지 않는다.

포함:
1. 존재 — PATH 에 바이너리가 있는가
2. 버전 — 우리가 실제로 쓰는 서브커맨드 기준의 최소 버전 충족 여부
3. 격리 능력 — 설정 홈 환경변수를 실제로 따르는가 (런타임 프로브)
4. 경로 건전성 — nvm/pyenv 등 버전 관리 디렉토리 밑이면 경고
5. 등급 — 등록된 계정에 따라 required / optional 동적 판정

제외: 설치·업그레이드 실행, CLI 설정 변경, 로그인 상태·신원 조회,
비CLI 의존성(Xcode, JDK), 네트워크 연결성.

## 구현 phase

각 phase 는 독립적으로 동작하고 커밋한다. phase 끝에서 사용자 확인을 받는다.

---

### Phase 1 — 레지스트리 + 존재 검사

내장 툴 레지스트리(Rust 상수 테이블)와 PATH 탐색, 평문 표 출력.

```
TOOL      PATH
gh        /opt/homebrew/bin/gh
aws       /usr/local/bin/aws
terraform 없음
```

- [ ] `secrets tools` 가 레지스트리의 모든 툴에 대해 경로 또는 "없음" 을 출력
- [ ] 레지스트리 항목 추가가 한 줄로 끝나는 구조

확인 질문: 툴 목록에 빠진 것 / 뺄 것이 있는가.

---

### Phase 2 — 버전 파싱 + 최소 버전 + 종료 코드

툴마다 버전 명령과 파서를 정의. 최소 버전은 사용하는 서브커맨드 기준으로 근거를 주석에 남긴다.

- [ ] 버전 컬럼 출력, 파싱 실패 시 "확인 불가" 로 표시하고 죽지 않음
- [ ] 최소 버전 미달 시 경고
- [ ] required 전부 충족 0 / 아니면 1 종료 코드 (이 단계의 required 는 고정 목록)

확인 질문: 각 툴의 최소 버전 기준이 타당한가.

---

### Phase 3 — 격리 능력 프로브  ★ 핵심

이 슬라이스의 진짜 산출물. 계정 분리 설계 전체가 이 전제 위에 있다.

임시 디렉토리를 설정 홈으로 지정하고 무해한 명령을 실행해,
(a) 그 디렉토리에 파일이 생기는가 (b) 기존 계정이 보이지 않는가 를 확인한다.

| 툴 | 환경변수 | 예상 |
|---|---|---|
| gh | `GH_CONFIG_DIR` | 지원 |
| gcloud | `CLOUDSDK_CONFIG` | 지원 |
| aws | `AWS_CONFIG_FILE` + `AWS_SHARED_CREDENTIALS_FILE` | 지원 |
| firebase | 미상 (configstore / XDG_CONFIG_HOME?) | **미확인** |

프로브는 임시 디렉토리에서만 동작하며 실제 설정을 절대 건드리지 않는다.

- [ ] 툴별 격리 지원 여부가 표에 표시됨
- [ ] **firebase 의 격리 지원 여부가 실측으로 판명됨**
- [ ] 미지원 툴은 "플래그 주입 필요" 로 표시

확인 질문: firebase 가 미지원일 때 `--account` 플래그 주입으로 갈지, 별도 처리할지.
→ 이 결과가 다음 슬라이스 `secrets run` 의 설계를 확정한다.

---

### Phase 4 — 경로 건전성 + 캐시

- nvm/pyenv/rbenv/asdf 경로 패턴 감지 후 경고
- 프로브 결과를 `~/.secrets/.cache/tools.json` 에 캐시.
  키는 바이너리 경로 + mtime + 버전. 하나라도 바뀌면 재프로브. `--refresh` 로 강제

- [ ] firebase 가 nvm 경로 경고로 표시됨
- [ ] 두 번째 실행이 체감상 즉시

---

### Phase 5 — 동적 등급 + `--json`

required / optional 을 고정 목록이 아니라 등록된 계정 기준으로 판정.
계정 레지스트리가 아직 없으면 기본 required 집합(`gh` `aws` `git` `ssh`)으로 동작.

- [ ] GCP 계정 0개면 gcloud 가 optional 로 표시
- [ ] `--json` 이 GUI 가 쓸 수 있는 구조로 출력
- [ ] 최종 표에 5개 항목이 모두 반영

---

## 슬라이스 완료 기준

1. 위 표가 완전한 형태로 출력된다
2. firebase 격리 지원 여부가 판명되어 다음 슬라이스 설계 미결이 해소된다
3. `--json` 이 GUI 에서 소비 가능하다
4. required 미충족 시 종료 코드 1
