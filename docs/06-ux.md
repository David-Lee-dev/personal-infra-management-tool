# UI/UX 개편

2026-09-24 결정. 시안: https://claude.ai/artifact/CuLSRL7oGaGKvcMowRmLG3 (디자인 캔버스, 7판 — 프로젝트 관리 7장만).
codex(gpt-6-sol)와 각자 설계한 뒤 비교해 정리한 결과다. 1판 승인("이대로 가자") 뒤, 비밀값 관리에 그친다는
지적에 따라 **운영 중심 2판**으로 범위를 넓혔다 — 인스턴스에서 무엇이 어떻게 실행되는지, 로컬 레포, 레포 기준
`.env` 동기화와 재배포까지 이 도구가 담당한다.

## 왜

- 메뉴가 저장 방식(GitHub · AWS · 기타)대로 나뉘어, "이 서버에 뭐가 있나", "이 앱이 뭘 쓰나"에
  답하려면 여러 화면을 오가야 한다. 로컬 PC 쪽을 넣을 자리도 없다.
- 상세 화면으로 들어가면 목록이 사라져 비교하거나 흐름을 따라가기 어렵다.
- 같은 자리의 버튼이 탭마다 다른 일을 한다.
- 터미널이 늘 30%를 차지하고, 시작할 때 도구 점검 기록으로 채워진다.
- 지금 처리할 것(폐기 예정 · 만료 · 확인 예정)이 한곳에 모여 있지 않다.
- 1판도 비밀값 관리에 그쳤다. 인스턴스에서 무엇이 어떻게 실행되는지, 로컬 레포, `.env`와 배포를
  담을 자리가 없었다.

## 구조 (2판)

```
운영     홈 · 프로젝트 · 호스트 · 로컬 레포 · 변경 이력
시크릿   자격 증명 · 계정
도구     도구 상태 · 작업 로그
```

- **홈** — 실행 현황(레포 × 환경 표)과 주의 필요, 최근 활동.
- **프로젝트** — 배포 단위인 레포를 제품(tuk · gonggugyeong · nemo · 개인)으로 묶은 목록. 레포
  상세는 환경 카드(prod · dev · local: 호스트 · 경로 · 커밋 · 프로세스 · .env 상태 · 할 수 있는 일),
  환경 변수 표(변수 × 환경, 출처: 시크릿 · 직접 입력한 값 · 설정), 배포 기록.
- **호스트** — "실행 중인 서비스"(레포 · 환경별 프로세스 · 포트 · 커밋 · 상태)가 먼저 나오고, 그다음 이 호스트에서 사용하는
  자격 증명 · 서버 계정 · 예약 작업이 나온다. 연결되지 않은 프로세스도 표시된다.
- **로컬 레포** — ~/workspace의 모든 리포(브랜치 · 변경 · 연결된 프로젝트). 이름이 일치해 보이는
  것은 "연결 제안"일 뿐, 연결은 사람이 한다.
- **변경 이력** — 계획 · 실행 · 확인 · 롤백 기록. 배포는 최상위 메뉴가 아니다 — 프로젝트 · 환경
  맥락 안에서만 의미가 있다.
- **시크릿** — 1판의 자격 증명 · 계정 · 폐기. 자격 증명마다 그것을 쓰는 변수 · 파일 · 배포로 가는 역링크.
- **작업 로그** — 작업이 실행 중이거나 실패할 때만 하단에 한 줄로 표시한다. ⌘K는 찾기 · 이동 · 읽기 전용 실행.

## 쓰는 일의 경계 (2판에서 바뀐 원칙)

1판의 "사용 위치는 등록만, 이 도구는 원격 파일을 고치지 않는다"를 **철회한다.** 사용자가 `.env` 동기화와
재배포를 이 도구에 맡기기로 했다. 대신:

- **호스트 · 경로 · 작업별 허용.** 조회 · 파일 읽기 · .env 쓰기 · 프로세스 제어 · nginx 전환 · 배포를
  따로 허용한다. 볼 수 있다고 해서 쓸 수 있는 것은 아니다. 비활성화된 버튼은 무엇이 없어서인지 알려 준다.
- **계획 → 실행 → 확인 → 롤백.** 계획은 대상 파일 지문 · 출처 버전 · 고정 커밋에 묶인다 —
  그사이 바뀌면 다시 계획한다. 변경 미리보기는 확인한 내용만 보여 준다.
- **`.env` 반영** — (3판에서 바뀜) 정본은 로컬 프로젝트의 환경별 파일(`.env.local` · `.env.<환경>`)이고, 서버로
  한 방향으로만 반영한다. 값은 가리고 지문으로 비교한다. 백업(웹 경로 밖, 600) → 임시 파일 → 한 번에 교체 → 다시 읽어 확인 → 선언된 단위만 재시작 →
  헬스 체크. 실패하면 백업으로 복원한다. 롤백은 파일과 프로세스만 되돌린다고 화면에 명시한다.
- **재배포** — 고정 커밋, lockfile, 빌드를 먼저 확인하고, 요청을 받는 단위는 새 프로세스를 실행해 헬스 체크한 뒤
  트래픽을 전환한다. nginx 백업은 sites-enabled 밖에 두고, `nginx -t` 통과 시에만 reload한다. 스케줄러는 기존 것을 중지한 뒤 새 것을 시작해
  겹치지 않게 하고, 예상 공백을 보여 준다. "무중단" 배지 대신 측정 결과(헬스 체크 · 5xx)를 보여 준다. 안전한 전환 방법이
  없는 단위는 "수동 전환 필요"로 표시한다.
- **감사 기록** — 누가 · 어떤 계획 · 대상 · 명령 종류 · 지문 · 결과 · 백업 위치. 비밀값은 기록 · 화면
  어디에도 남기지 않는다.

`docs/02-aws-iam.md` · `docs/03-etc.md`의 "등록만" 규칙은 구현 전에 이 경계에 맞게 고쳐 쓴다.

## 원칙

- 증거의 출처를 구분한다: **등록됨**(사람이 등록) · **스캔됨**(도구가 읽음) ·
  **검증됨**(실제 동작 확인). 확인에는 시각이 붙고, 오래된 확인은 유효하지 않다.
- 로컬 스캔은 값을 읽지 않는다. 이름 · 경로 · 키 ID · 파일 메타데이터만.
- 파괴적인 작업은 확인 시트에서 대상 · 근거 · 되돌릴 수 있는지를 보여 준 뒤 실행한다.
- 상태는 색뿐 아니라 텍스트로도 표시한다.

## 3판 — 프로젝트 중심 (프로젝트 관리 탭)

2026-09-24 결정. 시안: 같은 캔버스 7판. 작업이 엉키지 않도록 캔버스에는 프로젝트 관리 화면만 남겼다 —
1·2판 시안(홈 · 호스트 · 시크릿 · .env · 재배포 등)은 캔버스 6판 이력에 있고, 해당 기능을 설계할 때 다시 그린다. 인프라 관리로 넘어오면서 관리 단위를 키에서
**프로젝트**로 바꾼다. 개발은 로컬에서 시작하고, 서비스로 내보내기로 하면 그때 서버가 붙는다. 한 번에 다
만들지 않고 프로젝트 관리 탭부터 진행하며, 홈은 마지막에 설계한다.

**모델.** 프로젝트 = 로컬 디렉토리 하나(= 레포 하나). 2판의 "제품 ─< 레포"는 **그룹**(tuk · gonggugyeong ·
개인)으로 낮춘다. 프로젝트에는 단계 순서대로 붙는다.

```
로컬(디렉토리) → Git(원격 레포 + coding 키) → 서버(환경 ─ 호스트 + deploy 키) … 자격 증명(필요할 때 환경별로)
```

**화면.**

- **사이드바** — 홈 · 프로젝트(그룹별 목록, 단계 점 3개: 로컬 · Git · 서버) · 인프라(호스트 · 자격 증명 · 계정) ·
  도구. AWS · GitHub 모아보기는 나중에 인프라 아래에 둔다.
- **목록** — 단계(로컬 · Git · 서버) · Git 원격 · 환경별 호스트 · 다음 할 일. 필터는 단계 기준.
  `~/workspace`에서 찾은 미등록 디렉토리는 배너로 제안만 한다.
- **새 프로젝트** — "새 디렉토리 만들기" 또는 "기존 디렉토리 등록". 이름 · 상위 디렉토리 · 디렉토리 이름
  (이름은 제안하지 않고 사용자가 입력한다. 경로는 Finder로도 고를 수 있고, `~/workspace` 안의 폴더만 받는다) · 그룹 · `git init`. 만들면 바뀌는 것을 옆에 보여 준다. 원격에는 아무것도
  만들지 않는다. 프로젝트를 삭제해도 디렉토리는 지우지 않고 기록만 보관한다.
- **프로젝트 상세** — 머리에 **단계 띠**(로컬 · Git · 서버 · 자격 증명). 다음 단계는 강조하고, 아직 못 하는
  단계는 이유를 적는다("서버는 GitHub에서 코드를 받아 갑니다. Git을 먼저 연결하세요"). 탭: 개요 · 환경 변수 ·
  자격 증명 · 변경 이력 · 설정. 로컬 단계의 개요는 브랜치 · 감지한 도구 · `.env` 파일(이름과 변수 개수만,
  `.gitignore` 여부), 운영 단계의 개요는 환경별 자격 증명과 환경 카드.
- **Git 연결** — GitHub 계정 → 새 레포(기본 비공개) 또는 기존 레포 → SSH 키 → 첫 push(기본 꺼짐).
  사전 점검(`.env*`가 `.gitignore`에 있는지, 추적 파일에 키 형식이 있는지, origin이 비어 있는지)과
  실행 계획(GitHub · 시크릿 · 로컬 구분)을 옆에 둔다.
- **서버 연결** — 인스턴스는 사용자가 AWS 콘솔에서 만든다. 이 도구는 인스턴스를 읽기만 한다. 인스턴스 선택
  (또는 주소 직접 입력) → 첫 접속(.pem을 시크릿 저장소로 가져오고 ubuntu는 비상용으로 등록) → 서버 준비
  (배포 · 관리 계정, 런타임, 읽기 전용 배포 키, clone) → 환경 이름 · 브랜치 · 경로. `.env` 반영 ·
  첫 배포 · 도메인 연결은 연결한 뒤 환경 화면에서 따로 계획하고 실행한다.
- **자격 증명 추가** — 프로젝트 안의 "＋ 자격 증명": IAM 발급(권한 하나 · 환경 하나) · 기존 자격 증명 연결 ·
  API 키/토큰 · 시크릿 파일. 발급 화면은 프로젝트와 환경이 채워진 채로 열린다.
  **프로젝트 화면에서는 자격 증명을 만들고 등록만 한다. 제거(삭제 · 연결 해제 · 폐기)는 하지 않는다**
  (2026-09-24 결정). 제거는 인프라 › 자격 증명 화면에서만 한다 — 프로젝트를 다루다 실수로 운영 중인
  키를 지우는 길을 두지 않기 위해서다.

**결정.**

- 로컬 push 키는 **프로젝트 전용 coding 키(쓰기 배포 키)**를 권장 기본으로, 계정 SSH 키는 선택지로 둔다.
  키는 `git config core.sshCommand`로 그 레포에만 지정한다. `~/.ssh/config`는 바꾸지 않는다.
- 서버는 레포별 **읽기 전용 deploy 키**로 코드를 받는다. 서버 접속 정보는 이 도구의 호스트 기록에만 둔다.
- 여러 단계에 걸친 작업(레포 생성 · 키 등록 · 서버 준비)은 어디까지 했는지 기록하고, 실패하면 멈춘다. 다시
  실행하면 이어서 진행한다. GitHub에 만든 레포는 자동으로 지우지 않는다.
- Git 사전 점검의 키 형식 검사만 예외적으로 파일 내용을 읽는다. 일치 여부만 보고 값은 표시하지 않는다.
- **런타임은 가정하지 않는다.** 프로젝트 파일에서 감지하고 근거 파일을 함께 보여 준다(예: `.nvmrc` ·
  `package.json` → Node, `pyproject.toml` · `.python-version` → Python, `Cargo.toml` · `rust-toolchain.toml` →
  Rust, `go.mod` → Go). 서버에는 감지한 런타임만 설치한다. 감지하지 못했거나 근거가 서로 맞지 않으면 설치하지
  않고 직접 지정하도록 요청한다. 프로세스 관리자 같은 실행 방식은 서버 준비가 아니라 첫 배포 때 정한다.
- **`.env`는 로컬이 정본이다.** 환경마다 로컬 파일 하나가 대응한다(`local` ↔ `.env.local`, 서버 환경 ↔
  `.env.<환경>`, 서버 연결 때 만든다). 반영은 로컬 파일 → 서버 `.env` 한 방향이고, 로컬 환경은 반영할 곳이
  없다. 서버에서 직접 바뀐 값이 있으면 반영 전에 알리고, 덮어쓸지 사용자가 정한다. IAM 발급은 그 환경의 로컬
  파일 변수에 값을 넣는다.
- **설명문은 일반 문장으로 쓴다.** 어떤 프로젝트 · 언어 · 서버에도 맞는 문장만 고정 문구로 둔다. 프로젝트마다
  다른 것(경로 · 버전 · 명령 · 파일 이름)은 감지 결과나 입력값 자리에만 들어간다.
- 시안의 ledger-lite는 예시 프로젝트다. 2판의 프로젝트 · 레포 화면(1줄)은 3판으로 대체한다.

## 단계

3판(프로젝트 관리)은 아래 순서로 만든다. 한 단계씩 확인하고 넘어간다.

1. ✅ 목록 · 새 프로젝트(새 디렉토리 · 기존 디렉토리 등록) · 로컬 단계 상세 · 왼쪽 메뉴의 프로젝트 목록.
   기록 `~/.secrets/projects/<이름>/project.toml`. git 상태 · 런타임 · 환경 변수 파일은 기록하지 않고 볼
   때마다 스캔한다. 상세의 Git 연결 · 서버 연결 · ＋ 자격 증명 버튼은 자리만 있다.
2. 등록하지 않은 디렉토리 찾기(작업 디렉토리 스캔 → 검토하고 등록).
3. ✅ Git 연결 — 점검(값이 올라갈 수 있는 `.env*`는 `.gitignore`에 추가, 이미 추적 중이면 막음) →
   git init(없으면) → 원격(이미 있는 origin을 그대로 쓰거나, 기존 레포 · 새 레포) → 키(시크릿 저장소의 그
   레포 키를 쓰거나, 없으면 쓰기 권한 배포 키를 새로 발급 — 기존 배포 키 절차를 그대로 부른다) →
   `core.sshCommand` → `git ls-remote`로 접속 확인. 원격에 만들기 전에 로컬에서 거절할 것은 모두 거절한다.
   실패하면 그 자리에서 멈추고, 다시 실행하면 이미 생긴 원격과 키를 이어 쓴다. push는 하지 않는다.
   키 용도의 기본값은 기존 기록과 같은 `develop`이다.
4. 서버 연결
   - ✅ 준비된 서버 잇기 — ① 인스턴스 → ② 그 인스턴스의 **확인된 배포 계정(sudo 없음)** → ③ 환경 이름.
     관리 계정은 목록에서 빼고 개수만 알린다. 배포 경로는 입력받지 않는다 — `/srv/<레포 이름>` 규칙으로
     정해진다. Git이 먼저 연결돼 있어야 한다(레포 이름과 코드를 받을 곳이 거기서 나온다). 그 계정의 키로
     서버에 들어가 배포 경로를 읽기만 한다 — 없거나 비어 있거나 같은 레포의 checkout이면 `project.toml`의
     `[[environments]]`에 기록하고, 다른 레포나 git이 아닌 디렉토리면 기록하지 않는다. 붙은 환경은
     [서버 확인]으로 언제든 다시 읽는다.
   - 새 인스턴스 준비(첫 접속 · 계정 만들기 · 런타임 설치)는 아직 자격 증명 › AWS 화면에서 한다. 프로젝트
     흐름으로 옮기는 일과 `.env.<환경>` 파일 만들기 · 코드 받기(clone)는 다음 단계다.
5. 자격 증명 추가 — IAM 발급 · 기존 자격 증명 연결 · API 키 · 시크릿 파일. 제거 없음.
6. `.env` 반영 — 로컬 파일 → 서버, 차이 확인 · 백업 후 적용 · 헬스 체크.

아래는 2판의 단계다. 3판과 겹치는 부분은 3판 순서를 따른다.

1. ✅ 셸 — 왼쪽 메뉴, 작업 로그 접기, 토큰, 목록 점 수정. (메뉴 구성은 2판에 맞춰 바꾼다)
2. 읽기 경로 — 로컬 레포 찾기, 호스트 스캔(pm2 · nginx · 포트 · 커밋) 스냅샷, 프로젝트 · 환경
   기록, 홈의 실행 현황 표. 쓰기 없음.
3. 시크릿 저장소 통합 — 자격 증명 통합 목록 + 인스펙터, 역링크.
4. .env — 환경 정의 · 가린 비교 · 변경 미리보기 → 허용된 경로에 백업 후 적용 · 확인 · 롤백.
5. 재배포 — 요청을 받는 단위부터(새 포트 · 헬스 체크 · nginx 전환), 그다음 스케줄러 · 복잡한 단위.
   리포마다 lockfile · pm2 설정이 다르므로(04-migration) 레시피가 없는 곳은 수동으로 남긴다.
6. 폐기 절차 — IAM 키 비활성화 등 1판 5단계.

## 용어

2026-09-24 codex와 검토해 정했다. 개발자가 콘솔에서 실제로 쓰는 말을 쓴다 — 순우리말로 풀어 새로
만든 말은 쓰지 않는다.

| 쓰지 않음 | 씀 |
|---|---|
| 이 맥 · 이 맥의 리포 | 로컬 · 로컬 레포 |
| 금고 · 금고 밖 | 시크릿(메뉴) · 시크릿 저장소(본문) · 미등록 |
| 들이기 · 들인 IAM | 가져오기(파일을 옮겨 옴) · 등록 · 등록한 IAM(기존 IAM 기록) |
| 소비처 · 넣을 곳 · 들어간 곳 | 사용 위치 |
| 맞추기 | 동기화 |
| 탐침 | 헬스 체크 |
| 되돌리기 · 미리 돌려보기 | 롤백 · 변경 미리보기 |
| 실행 단위 · 여기서 실행 중 · 돌아가는 것 | 프로세스 · 실행 중인 서비스 · 실행 현황 |
| 주의할 것 · 한눈에 | 주의 필요 · 개요 |
| 기록됨 · 조사에서 발견 · 동작 확인 | 등록됨 · 스캔됨 · 검증됨 |
| 조사 · 다시 조사 | 스캔 · 다시 스캔 |
| 도구 검사(메뉴) · 작업 창 · 활동 | 도구 상태 · 작업 로그 · 변경 이력 |
| 정리 대상 · 정리 순서 · 분류 해제 | 폐기 예정 · 폐기 절차 · 지정 해제 |
| 기록 밖 | 미등록 |
| 삭제 가능 | 삭제 가능 예정일 (다시 쓰이면 다시 계산) |
| 할 수 있음 | 허용된 작업 |
| 깨끗함 · 직접 값 · 평문 비밀 파일 | 변경 없음 · 직접 입력한 값 · 평문 시크릿 파일 |
| 걷어내기(서버 계정) | 서버에서 제거 |

그대로 쓰는 말: 호스트 · 자격 증명 · 계정 · 환경 변수 · 배포 · 재배포 · 재시작 · 비활성화 · 키 ID ·
연결 제안 · 백업 후 적용 · 인프라 콘솔.

문구 규칙:

- 식별자와 도구 이름은 그대로 쓴다 — `IAM` · `.env` · `pm2` · `nginx` · 브랜치 · 경로. 조사(에서 · 을 · 는)는 붙여 쓴다
  ("AWS에서", "`.env` 파일").
- ` · `는 짧은 메타 정보에만 쓴다. 동작과 경고는 문장이나 별도 버튼으로 표현한다.
- 버튼은 짧은 동작("다시 스캔", "동기화 계획", "키 비활성화"), 설명은 "-습니다"로 끝나는 온전한 문장,
  상태 칩은 명사나 짧은 상태.
- 결과를 이름 붙인다. "검증됨"에는 무엇을 언제 확인했는지, "롤백"에는 무엇을 되돌리는지를 함께 적는다.
  모든 것을 되돌릴 수 있다고 약속하지 않는다.

화면 문구, 오류 메시지, 문서에 적용했다. 보관 기록 파일(`archived.toml`)의 키는 계정 보관 기록과 같은
`archived_at` · `reason` 으로 통일했다. 코드 주석은 아직 옛 표현이 남아 있다.
