# 서버 관리

2026-09-27 설계. SSH 접속(`~/.ssh/config` 별칭 만들기)을 걷어내고, 그 자리에 **서버 관리**를 둔다.
시안: https://claude.ai/artifact/CuLSRL7oGaGKvcMowRmLG3 (디자인 캔버스 12판, 둘째 줄 — 서버 목록 · 제안 · 등록 · 상세 · 계정 추가 ·
프로젝트 서버 연결 · 사이드바).

## 왜

- `~/.ssh/config`에 별칭을 적는 이유는 접속을 짧게 하려는 것이다. 접속 정보를 이 도구가 들고 있으면
  별칭 없이 버튼 하나로 터미널(Ghostty)을 열어 바로 들어갈 수 있다. 별칭 파일을 만들고 `Include`로
  합치는 일은 필요 없어졌다.
- 지금은 "서버"라는 기록이 없다. 서버 계정이 AWS pem 경로(`keys/aws/<계정>/<머신>/<리전>/<키페어>/
  instance/<인스턴스>/<로그인>/`) 아래에 흩어져 있고, 인스턴스 이름 · 주소가 계정마다 · 프로젝트
  환경마다 복사되어 있다. IP가 바뀌면 고칠 곳이 여럿이다.
- AWS 밖의 서버도 있다 — nemo(Tailscale), nemo-mac(Mac mini). 이들은 `~/.ssh/config`에 손으로 적혀
  있을 뿐 이 도구가 모른다. 구조가 AWS에 맞춰지지 않도록 **처음부터 AWS 밖의 서버를 같은 모양으로 다룬다**
  (2026-09-27 사용자 결정).

## 원칙

- **서버가 주소의 정본이다.** 주소 · 포트는 서버 기록 한 곳에만 둔다. 계정 · 프로젝트 환경은 서버를
  가리키기만 하고, 접속 · 배포 · `.env` 반영 · 코드 받기는 쓸 때 서버 기록에서 주소를 읽는다.
- **AWS는 서버의 속성일 뿐이다.** 서버의 종류(EC2 · Lightsail · 기타)와 AWS 계정 · 리전 · 인스턴스 ID는
  보여 주는 사실이다. 접속 · 계정 만들기 · 배포는 종류와 무관하게 "주소 + 계정 + 키"로만 한다.
- **pem도 계정 하나로 본다.** EC2의 `ubuntu`는 "pem 키로 들어가는 계정"이다. 계정 만들기에 쓰는
  계정(관리 접속)은 서버마다 사용자가 지정한 sudo 계정 하나다 — AWS면 보통 pem의 `ubuntu`, 로컬 서버면
  사용자가 원래 쓰던 관리자 계정.
- **키가 어디 있든 계정은 같은 모양이다.** 이 도구가 만든 키 · 시크릿 저장소로 가져온 키 · 로컬의 키 파일
  경로 · ssh 기본 키(ssh-agent · `~/.ssh/id_*`) 중 하나를 가리킨다.
- **기존 키 파일은 옮기지 않는다.** 사용자가 직접 쓴 `~/.ssh/config`가 시크릿 저장소 안의 키 경로를
  `IdentityFile`로 가리키고 있다(tukapp-prod 등). 옮기면 그 접속이 끊긴다. 기존 계정은 지금 자리의 키를
  가리키고, 새로 만드는 계정만 새 자리에 둔다.
- 도구 전체 원칙은 그대로다 — 이름 · 계정 · 그룹은 사용자가 정하고, 도구는 읽은 사실을 보여 준다.
  자동으로 등록하지 않고 제안만 한다. 제거는 기록을 보관소로 옮긴다.

## 데이터

```text
~/.secrets/servers/<id>.toml            서버 한 대 — 속성과 계정 목록. 값(키)은 없다
~/.secrets/keys/server/<id>/<로그인>/   이 도구가 새로 만든 계정 키 (key · key.pub)
~/.secrets/keys/aws/…/instance/…/       기존 계정 키 — 그 자리에 둔다
~/.secrets/archive/servers/<시각>-<id>/ 등록 해제한 서버 기록
```

```toml
id    = "tuk-api-server"        # 도구가 등록 때 이름에서 만든다. 바뀌지 않는다. 화면에는 name만 나온다
name  = "tuk-api-server"        # 사용자가 정한다. 바꿀 수 있다
group = "툭"                    # 선택. 프로젝트 그룹과 같은 목록에서 고른다
address = "54.116.119.214"      # IP 또는 DNS
port    = 22
kind    = "ec2"                 # ec2 | lightsail | other
admin   = "ubuntu"              # 관리 접속 — 계정 만들기 · 서버 준비에 쓰는 sudo 계정. 없을 수 있다
workspace = "/srv"              # 계정 만들 때의 기본값 (공용 작업 디렉터리 · 그룹)
workspace_group = "workspace"
note = ""
registered_at = "…"

[aws]                           # kind 가 ec2 · lightsail 일 때만. 보여 주는 사실
account  = "320042238085"
region   = "ap-northeast-2"
instance = "i-0b97076038cc8a4d3"

[[accounts]]
login   = "ubuntu"
role    = "admin"               # admin(sudo) | user
purpose = "비상용"
key     = { kind = "pem", keypair = "tuk-key" }     # 아래 "키" 참고
origin  = "existing"            # created(이 도구가 만듦) | existing(원래 있던 계정)
state   = "verified"            # local | installed | verified | unknown
verified_at = "…"

[[accounts]]
login = "deploy"
role  = "user"
key   = { kind = "vault", path = "keys/aws/…/instance/i-0b97…/deploy/key" }
origin = "created"
state  = "verified"
```

**키(`key`)의 종류.**

| kind | 뜻 | 쓰는 예 |
|---|---|---|
| `vault` | 시크릿 저장소 안의 키 파일(저장소 기준 상대 경로). 이 도구가 만들었거나 가져온 것 | 이 도구가 만든 deploy · admin |
| `pem` | 그 AWS 키 페어의 pem. 자격 증명 › 서버 키의 것을 가리킨다 | EC2 `ubuntu`, vpn(Lightsail) `ubuntu` |
| `file` | 로컬의 키 파일 경로. 가리키기만 하고 복사하지 않는다 | nemo-mac `~/.ssh/nemo-mac` |
| `agent` | 지정하지 않음 — ssh-agent · `~/.ssh/id_*` | nemo `infra` |

**프로젝트 환경**(`project.toml`의 `[[environments]]`)은 `server = "<id>"` · `login`으로 서버와 계정을
가리킨다. 지금 적혀 있는 `aws_account` · `machine` · `region` · `keypair` · `instance` · `instance_name` ·
`address`는 옮길 때 서버를 찾는 데만 쓰고, 새로 쓸 때는 적지 않는다.

**계정 기록의 정본은 서버 기록이다.** 지금 키 옆에 있는 `key.toml`은 옮긴 뒤 읽지 않는다(지우지 않고
둔다 — 되돌릴 때 근거가 된다).

### 서버 등록

한 화면(모달). 등록은 기록만 만든다 — 서버에 아무것도 쓰지 않는다.

1. **종류** — EC2 · Lightsail · 기타(로컬 · 다른 클라우드).
2. **서버** — 이름 · 그룹(선택) · 주소 · 포트(22). AWS면 AWS 계정 · 리전 · 인스턴스 ID(선택, 보여 주는 사실).
3. **처음 쓸 계정** — 최소 하나. 로그인 · 역할 · 키(종류에 맞는 기본값: AWS → 그 키 페어의 pem과 `ubuntu`,
   기타 → 키 파일 선택 또는 ssh 기본 키). [접속 확인]은 그 계정으로 들어가 `true`를 돌려 본다(선택).
   이 계정이 sudo가 있으면 관리 접속으로 지정할지 묻는다. (구현: 등록한 뒤 그 계정으로 한 번 들어가 본다 —
   등록 전에는 서버 기록이 없어 접속 확인을 따로 두지 않았다. 실패해도 등록은 남고 이유는 작업 로그에 남는다.)

AWS 서버의 pem은 자격 증명 › 서버 키에 먼저 가져와 있어야 한다. 없으면 그 탭으로 가는 링크를 보여 준다.

### 제안 살펴보기 (옮기기)

도구가 찾은 미등록 서버를 한 번에 보여 주고, 사용자가 고른 것만 등록한다.

- **서버 계정 기록에서** — `keys/aws/…/instance/<인스턴스>/<로그인>/key.toml`을 인스턴스별로 묶는다. 이름 ·
  주소 · 키 페어는 기록에서, 계정은 그대로(`vault` 키), pem의 `via` 계정(`ubuntu`)을 `pem` 키 · 관리 접속으로
  더한다. 5대.
- **`~/.ssh/config`에서** — 주소(HostName)로 묶는다. User → 계정, IdentityFile → `vault`(시크릿 저장소 안이면) ·
  `file` · `agent`. 위 5대와 주소가 같은 별칭(tukapp-prod 등)은 같은 서버로 합친다. 새로 나오는 것: nemo ·
  nemo-mac · vpn.
- 한 줄 = 제안 서버 하나. 이름(편집 가능) · 주소 · 계정들 · 근거(어느 기록 · 어느 별칭에서 왔는지) · 체크박스.
- `LocalForward` 같은 별칭의 다른 설정은 옮기지 않는다 — 제안 줄에 "옮기지 않는 설정: LocalForward"로 적는다.
- 등록하면 그 서버를 쓰는 프로젝트 환경을 서버로 잇는다(환경의 `instance` 또는 `address`로 찾는다).

### 서버 상세

```
  주소 · 포트 · 종류 · AWS · 공용 작업 디렉터리 /srv (그룹 workspace) · 메모 · 등록한 시각
```

- **계정 줄**: 로그인 · 역할 · 용도 · 키 종류(pem · 파일 · 기본 키일 때만 적는다) · 상태 · [접속]. `⋯`에는
  ssh 명령 복사 · 접속 확인 · (이 도구가 만든 계정) SSH 키 다시 등록 · 서버에서 제거 · (원래 있던 계정) 등록 해제.
- **＋ 계정**: 두 갈래.
  - *서버에 새로 만들기* — 관리 접속 계정으로 들어가 만든다. 지금 pem 화면의 계정 만들기를 옮긴 것이다
    (점검 · 준비 · 여러 계정 · 다른 서버에 있는 계정 이름 버튼). 인스턴스 · 주소는 서버 기록에서 온다.
    관리 접속이 없으면 이 갈래를 비활성화하고 이유를 적는다.
    서버에 같은 로그인 이름이 이미 있으면 로컬 기록에 없어도 키·권한을 건드리지 않고 거부한다.
    다른 이름(예: `deploy-garden`)을 입력해야 한다.
    공용 `/srv` 배포 경로와 그룹 권한은 이 이름 검사로 분리되지 않는다.
  - *원래 있는 계정 등록* — 로그인 · 역할 · 키만 적는다. 서버에 쓰지 않는다. [접속 확인]으로 확인.
- **편집**: 이름 · 그룹 · 주소 · 포트 · 관리 접속 · 공용 디렉터리 · 메모 · AWS 사실. 주소를 바꾸면 "이 서버의
  계정 N개와 환경 M개가 새 주소로 접속합니다"를 저장 전에 보여 준다.
- **등록 해제**: 이 서버를 쓰는 프로젝트 환경이 있으면 막고 그 환경을 보여 준다. 없으면 두 번 눌러 확인하고,
  서버 기록을 보관소로 옮긴다. 이 도구가 만든 계정이 서버에 남아 있으면 첫 누름에 그 사실을 적는다(서버의
  계정은 지우지 않는다). 키 파일은 그대로 둔다.

### 프로젝트의 서버 연결 · 환경 편집

자격 증명 연결처럼 **고르기만** 한다.

1. 서버 — 등록된 서버 목록(이름 · 주소 · 종류 · 그룹). 등록된 서버가 없으면 "서버에서 먼저 등록하세요"와
   [서버로 가기].
2. 계정 — 고른 서버의 계정 전부. sudo · 접속 확인 여부 · 이미 쓰는 환경을 사실로 적는다. 기본 선택은 없다.
3. 환경 이름 · 배포 경로 · 브랜치 — 지금과 같다. 고른 계정으로 배포 경로를 읽는 확인도 그대로다.

환경 카드의 서버 이름은 서버 상세로 가는 링크다.

### 자격 증명 › 서버 키(pem)

pem 상세의 "계정" 칸을 뺀다. 대신 **"이 키로 들어가는 서버"** — 그 pem을 `pem` 키로 쓰는 계정이 있는 서버
목록(이름 · 계정) — 과 서버 상세로 가는 링크를 둔다. 계정 만들기는 서버 상세로 옮겨졌다고 적는다.

## 접속 (Ghostty)

지금의 `hosts::terminal::open_ssh`를 넓힌다.

```
/usr/bin/env TERM=xterm-256color /usr/bin/ssh [-p <포트>] [-i <키> -o IdentitiesOnly=yes] <로그인>@<주소>
```

- `agent` 키면 `-i` · `IdentitiesOnly`를 빼 ssh 기본 동작에 맡긴다. 포트가 22면 `-p`를 뺀다.
- 값은 지금처럼 셸이 달리 읽을 글자가 없을 때만 받는다(키 경로 · 로그인 · 주소 · 포트).
- 사용자의 `~/.ssh/config`의 `Host *` 설정은 그대로 적용된다 — 도구가 막지 않는다.
- 명령 복사는 같은 줄을 클립보드에 넣는다.

도구가 스크립트를 돌릴 때(서버 확인 · 배포 등)의 `ssh::run`도 같은 방식으로 포트 · 키 종류를 받는다.

## SSH 접속 걷어내기

- 코드: `secrets-core::ssh`, `secrets-local::ssh`, `command/ssh.rs`, `ui/ssh/`, 관련 dto · wiring, 서버 계정이
  바뀔 때 conf를 다시 만들던 호출.
- `~/.ssh/config` 맨 위의 도구가 넣은 두 줄(주석 · `Include ~/.secrets/ssh/*.conf`)을 지운다. 지우기 전에
  원본을 `~/.secrets/archive/ssh-config/<시각>/config`에 보관한다. 심볼릭 링크면 가리키는 파일에 쓴다.
  다른 줄은 건드리지 않는다(2026-09-27 사용자 승인). 앱 기능이 아니라 한 번 하는 정리다.
- 사용자가 직접 쓴 `~/.ssh/config` 블록은 그대로 둔다. 서버를 등록한 뒤 지울지는 사용자가 정한다.

## 이번에 하지 않는 것

- AWS에서 인스턴스 목록 불러오기 — 등록은 손으로(또는 제안에서) 한다.
- 별칭의 다른 설정(`LocalForward` · `ProxyJump` · `SetEnv` 등)을 계정에 두기.
- 비밀번호 로그인 — 도구가 쓰는 ssh는 `BatchMode`다. 키가 없는 계정은 등록할 수 없다.
- IAM · 기타 자격 증명의 사용 위치 호스트(`tukapp-prod` 같은 `~/.ssh/config` 별칭)를 서버로 바꾸기. 지금은
  `~/.ssh/config`를 읽어 주소로 환경을 찾는다. 서버를 등록한 뒤 다음 단계로 옮긴다.
- 기존 계정 키 파일을 새 자리로 옮기기.
